# Getgems Public API

Данная документация описывает основные сценарии использования **Getgems Public API**, в частности методов из секции `ReadApi`.

Приобрести доступ к API можно здесь: _[добавьте ссылку]_.

## Важные моменты

- Не превышайте лимит **300 запросов за 5 минут**, то есть в среднем не более **1 RPS**.
- API предоставляет данные и методы для формирования транзакций, но **не взаимодействует напрямую с вашим платёжным кошельком**.
- API не выполняет покупку NFT от имени конкретного кошелька. Для выполнения операции необходимо самостоятельно подписать сформированную транзакцию и отправить её в блокчейн.

# Создание торгового бота

Ниже описан рекомендуемый способ отслеживания новых событий и покупки NFT.

## 1. Получение начального cursor

После запуска приложения необходимо один раз получить актуальное значение `cursor`.

### Для подарков

```http
GET /v1/nfts/history/gifts?limit=1
```

### Для стикеров

```http
GET /v1/nfts/history/stickers?limit=1
```

### Для конкретной коллекции

```http
GET /v1/collection/{collectionAddress}?limit=1
```

Из ответа необходимо сохранить:

```text
response.cursor
```

Этот `cursor` будет использоваться для дальнейшего получения новых событий истории.

---

## 2. Получение новых событий

После получения начального `cursor` необходимо периодически запрашивать новые события.

Не выполняйте запросы чаще **1 раза в секунду**.

### Для подарков

```http
GET /v1/nfts/history/gifts?limit=10&reverse=true&after={cursor}
```

### Для стикеров

```http
GET /v1/nfts/history/stickers?limit=10&reverse=true&after={cursor}
```

### Для конкретной коллекции

```http
GET /v1/collection/{collectionAddress}?limit=10&reverse=true&after={cursor}
```

Ключевое отличие от шага 1 — использование параметров:

```text
reverse=true
after={cursor}
```

Шаг 1 необходим только для получения актуальной начальной позиции в истории.

После каждого запроса на шаге 2 необходимо сохранять новое значение:

```text
response.cursor
```

и использовать его в следующем запросе.

> При каждом перезапуске приложения рекомендуется снова выполнять шаг 1 и получать актуальный `cursor`.

Если необходимо отслеживать несколько коллекций подарков, целесообразнее использовать общий endpoint:

```http
GET /v1/nfts/history/gifts
```

вместо отдельных запросов:

```http
GET /v1/collection/{collectionAddress}
```

для каждой коллекции.

Это позволяет сократить количество запросов к API.

---

## 3. Фильтрация событий

На шаге 2 события истории возвращаются в:

```text
response.items
```

При необходимости можно ограничить типы возвращаемых событий с помощью query-параметра `types`.

Например, чтобы получать только события выставления подарков на фиксированную продажу или аукцион:

```http
GET /v1/nfts/history/gifts?limit=10&reverse=true&after={cursor}&types[]=putUpForSale&types[]=putUpForAuction
```

Каждый элемент `response.items` содержит:

```text
typeData.version
```

Значение `version` необходимо сохранить, если вы планируете использовать событие для покупки NFT на следующем шаге.

---

## 4. Получение транзакции для покупки NFT

Если на шаге 3 было обнаружено подходящее событие выставления NFT на продажу и вы хотите приобрести NFT, используйте:

```http
POST /v1/nfts/buy-fix-price/{nftAddress}
```

В `BODY` запроса необходимо передать `version`, полученную из события истории:

```json
{
  "version": "версия_из_шага_3"
}
```

Передача `version` позволяет убедиться, что покупка производится на основании актуального состояния NFT.

---

## 5. Подписание и отправка транзакции

В ответ на запрос из шага 4 API вернёт данные, необходимые для формирования транзакции.

Далее необходимо:

1. подписать транзакцию вашим кошельком или приватным ключом;
2. отправить подписанную транзакцию в TON Blockchain.

Для отправки подписанной транзакции в блокчейн можно, например, использовать бесплатный API:

https://tonapi.io

# Мониторинг всех активных листингов коллекции

Этот сценарий подходит, если вашему приложению необходимо поддерживать локальный список всех доступных листингов определённой коллекции.

Например, вы можете использовать его для отображения всех доступных NFT коллекции **Anonymous Telegram Numbers**.

В этом сценарии используются два параллельных процесса:

1. первоначальная загрузка всех активных листингов;
2. отслеживание последующих изменений через историю событий.

---

## 1. Первоначальная загрузка листингов

Необходимо последовательно получить все доступные листинги коллекции:

```http
GET /v1/nfts/on-sale/{collectionAddress}?limit=100
```

В первом запросе параметр `after` передавать не нужно.

Если API возвращает:

```text
response.cursor
```

следующий запрос должен выглядеть так:

```http
GET /v1/nfts/on-sale/{collectionAddress}?limit=100&after={cursor}
```

На каждой следующей итерации необходимо использовать `response.cursor` из предыдущего ответа.

Полученные листинги следует сохранять локально — например, в базе данных или кеше приложения.

Рекомендуемый интервал между запросами к данному endpoint — **не менее 2 секунд**.

Загрузка считается завершённой, когда API возвращает:

```text
cursor = null
```

---

## 2. Параллельное отслеживание изменений через историю

Одновременно с первоначальной загрузкой листингов необходимо начать получать события истории коллекции.

Это важно, поскольку состояние коллекции может изменяться в процессе выполнения шага 1.

### 2.1. Получение cursor истории

Выполните:

```http
GET /v1/collection/{collectionAddress}?limit=1
```

и сохраните:

```text
response.cursor
```

> Этот `cursor` относится к истории событий и никак не связан с `cursor`, используемым на шаге 1 для пагинации `/v1/nfts/on-sale`.

---

### 2.2. Получение новых событий

Далее необходимо периодически выполнять:

```http
GET /v1/collection/{collectionAddress}?limit=10&reverse=true&after={cursor}
```

Не выполняйте этот запрос чаще **1 раза в 2 секунды**.

После каждого ответа обязательно обновляйте локальное значение:

```text
cursor = response.cursor
```

Полученные события необходимо применять к локально сохранённым данным о листингах.

Например:

- новый листинг — добавить NFT;
- изменение цены — обновить NFT;
- продажа или отмена листинга — удалить NFT из списка активных листингов.

---

## После завершения первоначальной загрузки

Когда шаг 1 полностью завершён и `/v1/nfts/on-sale/{collectionAddress}` вернул:

```text
cursor = null
```

продолжать повторную полную загрузку листингов не требуется.

После этого достаточно постоянно выполнять шаг **2.2** и поддерживать локальное состояние коллекции актуальным на основании событий истории.

Таким образом:

```text
/v1/nfts/on-sale
```

используется для получения первоначального snapshot состояния коллекции, а:

```text
/v1/collection/{collectionAddress}
```

— для последующего отслеживания изменений.
